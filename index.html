Win-to-Race

A native macOS app that races multiple AI coding agents on the same real engineering task. One repository and one problem go in — isolated agent runs, live logs, ADRs, feedback records, and comparable results come out.

View on GitHub Build & Run Task Format Docs

How It Works

Win-to-Race discovers which AI coding CLIs are installed on your Mac, then orchestrates them in parallel on the same task. Each agent works in full isolation so you can compare outputs objectively.

Define a Task

Describe the problem in Simple Mode (one-shot) or write a structured Markdown task file for Advanced Mode.

Select Agents

Win-to-Race auto-detects installed CLIs. Pick which agents should compete, or let all available ones race.

Parallel Execution

Each agent gets its own Git branch, workspace directory, environment, and live log stream. No interference between runs.

Compare & Learn

Review diffs, runtime metrics, and generated ADRs side by side. Rate results to build long-term learning data.

Supported Agents

Ten agent providers are supported out of the box. Native CLIs are called directly; others are routed through aider with provider-specific model configuration.

Everything you need to orchestrate, observe, and evaluate AI coding agents without leaving your Mac.

  • Automatic CLI discovery via PATH scanning

  • Live streaming logs with pending-question detection
  • Keychain-backed API key storage
  • Per-agent workspace and environment isolation
  • Generated Architecture Decision Records (ADRs)

  • Advanced Mode for structured task queues
  • Environment variable editor for provider keys
  • Built with SwiftUI for native macOS look and feel

Two Modes of Operation

Simple Mode

Point Win-to-Race at a local repository, describe the problem in plain text, and hit Start. All detected agents race on the same prompt. Ideal for quick bug fixes, refactors, or feature spikes where setup overhead should be zero.

Advanced Mode

Write structured Markdown task files with Repository, Title, Description, and optional Constraints sections. Import multiple tasks at once for batch evaluation. Built for systematic benchmarking and repeatable experiments.

Task Format

Advanced Mode uses Markdown files that are easy to read, write, and version-control. Here is a complete example:

# task.md ## Repository https://github.com/org/project ## Title Fix websocket reconnect issue ## Description Users lose their connection after the laptop wakes from sleep mode. The client should detect the dropped socket and reconnect with exponential backoff. ## Constraints - Do not modify the auth layer - Keep backward API compatibility - Add integration tests for the reconnect flow

Architecture Overview

Win-to-Race is a single-target SwiftPM executable built for macOS 14+. The architecture follows a unidirectional data flow with a central AppStore driving all views.

+------------------------------------------------------------------+ | Win2RaceApp (SwiftUI lifecycle) | +------------------------------------------------------------------+ | | | AppStore (@MainActor, ObservableObject) | | +------------------------------------------------------------+ | | | State: tasks, runs, installations, secrets, diagnostics | | | +------------------------------------------------------------+ | | | | | +----------------+----------------+ | | v v v | | +-----------+ +------------+ +-------------+ | | | Dashboard | | SimpleTask | | AdvancedMode| | | | View | | View | | View | | | +-----------+ +------------+ +-------------+ | | | | | +-----------+ +-------------+ +-------------+ | | | Setup | | Learning | | Diagnostics | | | | View | | View | | View | | | +-----------+ +-------------+ +-------------+ | | | +------------------------------------------------------------------+ | Services | | +-------------------+ +------------------+ +----------------+ | | | OrchestratorEngine| | CLIDetector | | KeychainService| | | | (run lifecycle) | | (PATH scanning) | | (API keys) | | | +-------------------+ +------------------+ +----------------+ | | +-------------------+ +------------------+ +----------------+ | | | ProcessRunner | | MarkdownTask | | FileBackedTask | | | | (subprocess I/O) | | Parser | | Store | | | +-------------------+ +------------------+ +----------------+ | | +-------------------+ +------------------+ | | | AgentPrompt | | SandboxProfile | | | | Factory | | Builder | | | +-------------------+ +------------------+ | +------------------------------------------------------------------+ | Persistence: ~/Documents/Win2Race/workspace (Markdown files) | +------------------------------------------------------------------+

What Each Agent Gets

Every agent run is fully isolated. No agent can see or affect another agent's work.

Own Git Branch

A dedicated branch named with the agent and task slug. All changes stay isolated until you decide to merge.

Own Workspace

A separate working directory under ~/Documents/Win2Race/workspace so file writes never collide.

Live Log Stream

Stdout and stderr are captured in real time. Pending questions from interactive agents are surfaced in the UI.

Runtime Report

Start time, end time, exit code, and duration are recorded automatically for every run.

Generated ADR

An Architecture Decision Record is written per run to document the approach the agent chose.

Feedback Record

After a run completes, rate the output. Feedback feeds the Learning view where per-agent success rates emerge over time.

Getting Started

Prerequisites

  • macOS 14 (Sonoma) or later
  • Xcode 16+ or Swift 6.0+ toolchain
  • At least one AI coding CLI installed (e.g. claude, gemini, codex, aider)
  • API keys for the providers you want to use

Build & Run

Clone the repository and use the included build script:

git clone https://github.com/GodModeAI2025/win2race.git cd win2race ./script/build_and_run.sh

The script compiles the SwiftPM target, stages dist/Win2Race.app, and launches the app as a proper macOS application bundle.
